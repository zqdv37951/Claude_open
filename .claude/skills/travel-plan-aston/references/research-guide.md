# 聯網調研指南

生成頁面前，用你所在 Agent 的**聯網搜尋 / 網頁抓取工具**補全資料（如 Claude Code 的 WebSearch/WebFetch、Codex 的聯網能力等）。**不查實時票價/機票價格**（易過期出錯）。

## 第三方 skill 適配（可選增強，有則用、無則降級） {#third-party}

調研開始前，先判斷**當前 Agent 是否可呼叫相關官方旅行類 skill / MCP**（使用者自行安裝的，如飛豬、高德、騰訊地圖、滴滴等）。**有就優先用它們拿對應資料，沒有就走本指南後面的靜態調研**——兩條路產出同一套 `trip` 資料結構，成品不因缺這些 skill 而殘缺。

下表為各家公開能力盤點（2026-06 調研一手開放平臺文件，**以各家官方文件實時為準**，能力會變）：

| 使用者若裝了 | 可優先用它拿（對應咱們哪個功能） | 備註 |
|------|------|------|
| **高德地圖** MCP/skill（增強面最大，多數工具開箱即用） | **地理編碼 → 精確座標**（替代"搜經緯度"猜）；**公交/駕車/步行/騎行路徑規劃 → 點到點交通**（實時路況+多方案）；**天氣查詢 → 行前須知天氣**；**POI 關鍵詞/周邊/詳情搜尋 → 景點&酒店資訊**；**生成專屬地圖 → 整條行程喚端地圖連結**；**導航/打車 → actionLink** | 調研到 15 個工具，是命中咱們薄弱點最多的一家。官方入口具名（2026-07 核）：**高德官方 MCP Server**（lbs.amap.com「大模型開發工具」入口）與 OpenClaw 平臺 skill **`amap-lbs-skill`**（GitHub org `AMap-Web`），均需使用者自備 Web 服務 Key |
| **飛豬 flyai** skill/MCP（實時直連官方庫，結果可真實預訂） | **機票搜尋 → 航班候選**；**酒店 → 酒店片區**；**景區門票/度假 → 門票**；均返回**真實預訂連結**作 actionLink | **需 API Key**；體驗版資料有缺 |
| **騰訊位置服務** skill/MCP（能力與高德重疊，開發向更重） | 路線規劃、POI 搜尋（8000 萬+）、地址服務、實時路況導航；另有 3D/室內地圖（一般用不上） | 多與高德二選一即可 |
| **滴滴** MCP/skill | **打車全流程**（叫車/預估/跟蹤/取消）→ 交通的用車方案與**叫車喚端連結**；也有駕車/公交/步行/騎行路線規劃 | Beta 版返回跳轉連結 |

沒裝任何一家時，全部走本指南後面的靜態調研，成品不缺區塊。

**座標系陷阱（用高德/騰訊必讀）**：高德與騰訊地圖返回的座標是 **GCJ-02**（國測局加密座標），而本 skill 的地圖用 OSM 瓦片（**WGS-84**）。直接把 GCJ-02 座標寫入 `trip`，中國境內點位會系統性偏移一百到幾百米——恰好製造你想避免的"座標錯位翻車"。**凡來自高德/騰訊的座標，寫入前必須用 `assets/map.js` 的 `gcj02ToWgs84(lat, lng)` 轉換**（境外座標該函式會原樣返回，多轉不會錯）。靜態調研（維基/搜尋）拿到的座標一般已是 WGS-84，不用轉。

**具體示例（點到點交通）**：本指南的「點到點交通」預設是靜態調研出一個方式+票價+耗時。若使用者裝了高德/騰訊地圖 skill，改用它的**路線規劃**（高德有公交/駕車/步行/騎行四種，公交含火車/地鐵/公交綜合方案），拿到結合**實時路況**的多方案（更科學合理），並把官方返回的導航連結作為該節點的 `actionLink`。另一個高價值點：用高德**地理編碼**拿精確座標，比"搜名稱+經緯度"可靠得多（座標錯位是地圖最常見的翻車點）。

**三條鐵律（破了就違背架構紅線）**：
1. **責任邊界**：用官方 skill 拿來的資料，其**實時性與真實性由該官方 skill 負責**，我們只做適配編排，不自行復核也不背書。
2. **標註來源 + 中性措辭**：凡用官方 skill 拿的資料，在頁面對應區塊註明資料來源（如「實時資料來源：高德地圖 skill，時效性由其保證」），與 AI 靜態整理的內容（標"參考·可能過時"）區分開；**用中性工程措辭，不誇、不推薦、不替任何一家打廣告**。
3. **行動連結只用官方返回的**：`actionLink` 的 URL **優先用官方 skill 返回的連結**（帶正確參數最穩）；**不要手拼 deeplink / URL scheme**（易失效）。官方 skill 不在場時，寧可不加行動連結，也別放可能打不開的手拼連結。（此禁令針對 actionLink；`map.js` 引擎按官方免 key URI 規範生成的點位連結（境內高德／境外 Google）不在此列，邊界見 `assets/page-contract.md#action-links`。）

> 本 skill 自身永遠不自行抓實時票價——實時資料只可能來自使用者已裝的官方 skill。詳見 `assets/page-contract.md#trip-data` 的 `dataSources` 與節點級 `actionLink` 欄位。

## 每個景點/酒店需採集

- 座標（lat/lng）：搜尋"<名稱> 經緯度 / coordinates"，或從地圖類結果取。
- 真實圖片 URL（**務必能載入**）：
  - **不要手拼** `upload.wikimedia.org/.../thumb/X/XX/...` 這種帶雜湊字首的直鏈——雜湊猜錯就 400/404。
  - 用穩健形式：`https://commons.wikimedia.org/wiki/Special:FilePath/<URL編碼的檔名>?width=600`，它會自動重定向到正確縮圖，無需雜湊。檔名取自該圖在 Commons 的真實檔名。
  - **每個圖片 URL 都要 `curl -s -o /dev/null -w "%{http_code}" -L <url>` 驗證返回 200 才用**；非 200（檔案不存在等）就換一張真實存在的圖，實在沒有就留空走 onerror 降級，絕不放已知打不開的連結。
  - **區分「驗證到打不開」和「本地環境連不到圖床」**：如果 `curl` 直接連線失敗（如企業代理/沙箱把 `commons.wikimedia.org`、`upload.wikimedia.org` 等圖床域名整個擋掉，返回連線錯誤而不是 HTTP 狀態碼），這不等於圖片本身打不開——目標讀者的瀏覽器很可能連得到，只是當前執行環境的網路受限。遇到這種情況：留空走 onerror 降級是安全的預設選擇，但**要在對話裡明確告訴使用者**「這次因為當前環境連不到圖床，沒能驗證/放上圖片，頁面會用色塊降級顯示，圖床本身不一定真的有問題」，不要讓使用者誤以為是圖片來源找不到或調研不完整。
- **`url` 必須跟圖片一樣驗證回 2xx／3xx**：`curl -sSL -o /dev/null -w "%{http_code}" -A "<瀏覽器 UA>" <url>`，或直接跑 `node assets/check-links.js <頁面>`。**頁面上完全看不出來，讀者點下去才發現**——這條規則的由來與實測數字見 `assets/check-links.js` 開頭的註解。
  - **HEAD 失敗不等於壞**：很多站台對 HEAD 回 405、對無 UA 的請求回 403。要用 GET + 瀏覽器 UA 再確認一次。
  - **404 與 DNS 解析失敗**幾乎確定是真的壞：換成已驗證的正確網址，或降級成地圖搜尋連結（`/maps/search/<名稱>/@lat,lng,16z`）。
  - **403 / 503 / 530 / 連線逾時**常是防爬或地區限制。**先在別的網路確認再動手**——把環境限制當成內容問題去改，只會把好連結換成更差的。這種情況要在對話裡告訴使用者「這幾個我驗不了」，不要默默改掉。
  - **替換路徑時不要做整串比對取代**：把 `/experiences` 全域換成 `/things-to-do`，會把 `/experiences/fairview-lookout-trail` 變成另一個 404。這個迴歸真的發生過，要逐條確認。
- 評分：來自點評類來源的概覽分（註明是概覽，非實時）。
- 一句話點評：綜合調研後用一句中文概括亮點。
- 營業時間 + 休息日（如"12:30–22:30，週日休"）：搜尋"<名稱> 營業時間 opening hours"。
- 門票參考價（如有）：給區間或單價，註明為參考、非實時。

## 新功能需要額外採集的四樣（容易漏）

這幾項是後來加的功能所需，舊的採集清單沒有涵蓋。**規則寫在契約裡，但資料要在調研階段就收齊**，否則生成時才發現缺，只能回頭重查。

- **座標的優先順序**：`poiWallHTML` 不看座標，但 `nearbyGridHTML` **第一步就 filter 掉沒有座標的項目**（不報錯、只是靜默變少）。所以**先確保「你希望出現在每站附近推薦面板的項目」有座標**；紀念品、通用美食品項這類本來就不對應單一地點的東西留在總覽牆即可。判斷與取捨規則（含「寧可沒有座標也不要填錯的座標」的理由）全部在 `assets/page-contract.md#highlights`，這裡只講調研動作：**先把要進附近面板的項目查到座標**，其餘留在總覽牆。
- **季節性目的地的「收季日」**：山區、國家公園、滑雪場、海濱、賞櫻賞楓等，**收季日要當成跟營業時間同等的必查項**。查法：搜「<名稱> closing date <年份>」「<名稱> season dates」，並以官方公告為準。查到了就填 `status`（`assets/conditional-features.md#season-status`）；查不到就在 `note` 寫「營運日期請出發前確認」並附官方連結，**不要放猜測的日期**——標籤的價值來自它是真的。
- **跨多據點行程要按「地區」分組收集**：行程跨越 3 個以上彼此相距 30 分鐘車程以上的據點時，`highlights` 改用 `regions` 結構，**每個地區各自收滿景點／美食／店家三類各至少 10 項**。調研時就按地區分頭收，不要收成一份全域清單再回頭拆——拆的時候會發現某個地區只有兩三項。
- **含健行的行程要收「距離 + 累計爬升」**：雙強度路線（`assets/conditional-features.md#dual-plans`）需要這兩個數字，而**累計爬升比距離更能反映難度**。查法：搜「<步道名> trail distance elevation gain」，優先取官方或步道資料庫的數字。只有距離沒有爬升的話，那條路線的難度標示等於沒有意義。

## 行前須知（按出發日期/季節定製）

- 天氣：搜尋"<城市> <出發月份> 天氣 平均氣溫 降雨"，給氣溫區間、降雨規律（如午後雷暴）、颱風/極端天氣季節提醒。
- 穿搭：據天氣給具體建議（含室內空調偏冷等本地常識）。
- 支付：當地主流支付方式（如香港八達通）、是否需備現金。
- 必備 App：交通、天氣、熱門景點排隊等。
- 購票時機：熱門景點建議提前幾天網上購票。

## 點到點交通

- 為關鍵行程點給出"如何到達"：方式（地鐵/巴士/纜車/輪渡/步行）、參考票價、耗時。搜尋"<A> 到 <B> 怎麼走 交通"。機場往返單獨給（如機場快線 vs 巴士的價/時對比）。

## 時令限定活動

- 搜尋"<城市> <出發月份> 活動 / 限定 / 展覽"，標註起止日期；對應景點 slot 寫入 `seasonal`。

## 天氣驅動排程

- 若目的地該季節有明顯午後高溫/雷暴/嚴寒等特徵：把戶外項目排在涼爽時段（上午、傍晚），午後/極端時段安排室內（商場、博物館、樂園），並在 `tips` 與當日 `tips` 中說明。

## 餐飲（每餐給必點菜 + 參考價）

- 每天給 1–2 餐具體推薦：餐廳名 + 營業時間/休息日 + 2–3 個必點菜及參考價。搜尋"<城市> <區域> 必吃 推薦 招牌菜"，對應 `day.dining` 欄位。

## 航班（待選，不查實時價）

- 使用者未預訂時，**給 3-5 個待選班次**（不要只給一個，萬一訂不上有備選）。
- 搜尋"<出發地>到<目的地> 航班 航空公司"，給真實存在的航司+航班號+大致時刻；`note` 寫機型/是否直飛/經停/大致價位區間（區間即可，不查實時價）。
- 已預訂的（使用者告知）單獨高亮，標"已預訂"。

## 酒店（按片區 + 價位推薦，不指定單一酒店）

- 先看本次行程各景點的地理分佈，**綜合選 1-2 個建議住宿片區**（如香港多落在尖沙咀/中環/銅鑼灣），寫明推薦理由（離哪些點近、交通如何）。
- 每個片區按 `經濟 / 中檔 / 高階` 三檔各給 1 個真實存在的代表酒店：名稱 + 大致每晚價位區間 + 一句話說明（位置/特點）。價位為區間參考，非實時房價。

## 免責宣告（必給，覆蓋全部資訊）

- **所有聯網整理的資訊**（天氣、航班、酒店、餐廳、景點、門票、價格、營業時間、評分、活動等）都可能不準或已過時，不只是機票/酒店。頁面必須給出覆蓋全部資訊的免責宣告，提示使用者到官方/訂票訂房/地圖等 App 核實後再決定。儘量給真實可信資訊，但不承諾與實時一致。
- **若部分資料來自使用者已裝的官方 skill**（見上節適配）：該部分實時性/真實性由對方官方 skill 負責，本頁只做適配呈現、不另行背書；免責宣告裡照樣提示以對應官方渠道為準即可（無需把責任攬到自己身上）。

## 提前預訂項與提前天數（餵給 reminders）

按經驗 + 聯網確認，標記需提前訂的項目並給 `leadDays`：

| 型別 | 建議提前天數 | 說明 |
|------|------------|------|
| 機票（國內） | 30 | 越早越便宜 |
| 機票（國際） | 45 | 含簽證緩衝請另列 |
| 跨城高鐵 | 15 | 放票後儘早 |
| 熱門景點/限流（如長白山、故宮） | 7 | 官方放票視窗 |
| 網紅餐廳/演出 | 3 | 需預約 |
| 酒店（旺季） | 30 | 旺季房緊 |

- 實際數值應結合目的地與季節聯網核實後微調，並在對話裡向使用者說明依據。
