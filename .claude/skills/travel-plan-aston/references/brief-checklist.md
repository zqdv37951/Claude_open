# Brief 清單

Mode A（從零規劃）開始前要釐清的東西。**核心規則:先把問題分成「該自己查的」與「該問使用者的」——查得到的絕不問。** 把自己的工作推給對方，換來的是更慢的迭代與更差的信任。

## 契約實際會分岔的 11 個地方

`SKILL.md` 早期只列了四項，實際上 `page-contract.md` 與 `conditional-features.md` 會分岔的地方有 11 個。漏掉第二層那七項，會做出「規格上合法但不該做」或「該做卻沒做」的頁面。

### 第一層:不問就不能開始（答錯要全部重做）

| 要問的 | 影響什麼 | 答錯的代價 |
|---|---|---|
| **交通方式**（自駕／包車／大眾運輸／有人載／請你建議） | 決定行程**能排什麼**。無車的話長距離風景公路那類點位直接排不進去 | 整份逐日行程作廢 |
| **清單顆粒度**（每天各十項 vs 每區各十項） | 決定用扁平 `highlights` 還是 `regions` 分區（門檻見 `assets/page-contract.md#highlights`） | 篇幅差三倍，做到第 300 項才發現 |
| **天數、人數、組成**（有長輩／小孩嗎） | 體力強度、餐廳份量、住宿房型、門票是買個人票還是車輛票 | 行程強度全錯 |
| **住宿狀態**（已訂／未訂請給選項／另做一份住宿規劃頁） | 未訂要給 `hotelAreas` 片區×價位；要規劃就多一份輔助頁（`assets/page-contract.md#page-types`） | 少一整個交付物 |

### 第二層:決定要不要做整塊功能

**這一層大部分你自己查得到**——目的地與日期一確定，下面前四項就有答案了。查完再決定要不要問。

| 判斷 | 觸發什麼 | 誰來回答 |
|---|---|---|
| 行程含健行／登山嗎 | 每日雙強度路線 + 雨雪備案（`assets/conditional-features.md#dual-plans`） | 多半自己判斷得出來 |
| 撞到連假／節慶／季節交界嗎 | 雙方案 A/B（同上）——**滿足才做，否則頁面白白膨脹兩倍** | **自己查**（查當地假日曆） |
| 目的地有季節性營運嗎 | 季節狀態標籤（`assets/conditional-features.md#season-status`）；調研時要把**收季日**當成跟營業時間同等的必查項 | **自己查** |
| 涉及航班與住宿嗎 | 不涉及就用 `transit` 取代（`assets/conditional-features.md#transit`） | 自己判斷 |
| 目的地語言環境 | 大量外文專有名詞就要做對照表（`assets/page-contract.md#glossary`） | **自己判斷**（北美的 Discovery Pass、Icefields Parkway 也算） |
| 城市行程還是荒野行程 | 要不要收 `photo`／`rating`／`review`（`assets/page-contract.md#blocks`）。判斷原則:這個站點是「有人在經營、會有服務品質差異」的地方嗎 | 自己判斷 |
| 要不要輔助頁 | 多一份 HTML，且**必須跟主頁互連**、共用 `travel-plan-theme`（`assets/page-contract.md#sibling-pages`） | **要問** |

### 第三層:不問也能做，但答了品質差很多

預算等級 · 飲食限制 · 體力上限（單段公里數與**累計爬升**，爬升比距離更能反映難度） · 護照國籍（簽證／eTA） · 特別想做的事（野生動物、溫泉、球賽、Outlet） · 輸出格式 · 有沒有裝第三方旅行 skill（有的話座標、路線、天氣、實時航班會準很多）

## 完整提問模板（可直接貼給使用者）

願意一次給完的人，把整張表貼過去。**不要刻意分輪**——分輪的唯一正當理由是「查完才知道要不要問」。
沒填的欄位不要追問，直接用預設值並在對話裡列成假設表。

```
════════ A. 骨架（這四項答錯要全部重做）════════

A1 日期／天數：            例：2026/10/1–10/12（12 天）
A2 出發地 → 目的地：       例：東京 → 卡加利（含近郊與國家公園）
A3 幾人、組成：            人數＿＿ ／ 有長輩？＿ 有小孩？＿ 年齡層＿＿
A4 交通：
     □ 自駕（我租車）   □ 有人載（朋友／家人）   □ 包車／導覽團
     □ 大眾運輸為主     □ 還沒決定，請你比較後建議
A5 住宿：
     □ 已訂好（請照我的住宿排動線）  → 旅館名稱與日期：＿＿＿
     □ 未訂，請給片區×價位選項
     □ 未訂，而且請另外做一份「住宿規劃頁」
A6 清單顆粒度：
     □ 每天各十項（逐日鋪開，適合單一據點）
     □ 每區各十項（按地區分組，適合跨多個據點；篇幅約三倍）

════════ B. 偏好（不填就用預設，但填了品質差很多）════════

B1 預算等級：   □ 經濟  □ 均衡（預設）  □ 不拘品質優先
                 住宿下限：□ 青旅床位可以  □ 要私人房  □ 要有廚房
B2 體力上限：   □ 輕鬆（單段步行 3km 內、以觀景台與纜車為主）
                 □ 中等（半天 5–10km，含累計爬升）
                 □ 高（全天 10km+）
                 □ 兩種都規劃（每天給輕鬆與中等兩條路線）
B3 飲食限制：   □ 無  □ 素食／蔬食  □ 清真  □ 不吃牛／豬  □ 過敏原：＿＿
B4 特別想做的： □ 野生動物  □ 溫泉  □ 看球賽／演出  □ Outlet 購物
                 □ 攝影（需要日出日落時間）  □ 其他：＿＿
B5 護照國籍：   ＿＿＿（我用它判斷簽證／eTA，不會用在別處）
B6 輸出格式：   □ 網頁 HTML（預設）  □ Markdown  □ 兩者都要

════════ C. 條件式功能（我多半自己判斷得出來，但你有想法就講）════════

C1 雙方案 A/B：  行程若撞到連假或季節交界，要不要給「參加」與「錯開」兩套完整排法？
                  □ 要  □ 不要  □ 你判斷（預設）
C2 輔助頁：      除了逐日行程，還要不要另外的單一主題頁？
                  □ 住宿規劃  □ 比價  □ 裝備清單  □ 都不要（預設）
C3 照片與評分：  站點卡片要不要放照片與評分？
                  □ 要（城市行程通常值得）
                  □ 不要（荒野行程的評分多半是雜訊，且 N 個站點就是 N 張圖，離線與檔案大小要付代價）
                  □ 你判斷（預設）
C4 已裝的旅行 skill：有裝高德／飛豬／騰訊地圖／滴滴嗎？有的話座標、路線、
                  天氣、實時航班會準很多。□ 有：＿＿＿  □ 沒有（預設走靜態調研）

════════ D. 這些我自己會查，不用回答 ════════

· 是否撞到當地連假或節慶
· 季節性設施的收季日（山區／國家公園／滑雪場／賞櫻楓）
· 需不需要外文名詞對照表（看目的地語言環境）
· 門票與交通票價的最佳組合（個人票 vs 車輛票 vs 通行證）
· 天氣區間與穿搭清單
· 每個站點的營業時間與休息日
· 簽證／eTA 規則（給我 B5 的國籍就好）
```

**D 段跟前面一樣重要。** 不列出「不用回答」的項目，對方會以為那些是你漏掉的，然後花時間去查你本來就會查的東西——這次那個最關鍵的發現（所有山區設施在同一天收季）就是查出來的，不是問出來的。

### 對應到契約的哪一條

| 欄位 | 決定什麼 |
|---|---|
| A4 交通 | 行程能排什麼（無車就排不進長距離風景公路） |
| A5 住宿 | `hotelAreas` 要不要給；是否多一份輔助頁（`assets/page-contract.md#page-types`） |
| A6 顆粒度 | 扁平 `highlights` 還是 `regions`（`assets/page-contract.md#highlights`） |
| B2 體力 | 是否做每日雙強度路線（`assets/conditional-features.md#dual-plans`） |
| C1 雙方案 | `trip.plans`（同上） |
| C3 照片評分 | `photo`／`rating`／`review` 要不要收（`assets/page-contract.md#blocks`） |
| C4 第三方 skill | 座標精度與 `trip.dataSources`（`references/research-guide.md`） |

## 問完之後

1. **把打算做的骨架攤出來讓對方確認形狀**，不是只確認參數。逐日主題、哪幾天在哪、哪幾天是機動——形狀錯了，參數再對也沒用。
2. **把剩下的假設列成一張表**寫在對話裡再動手。對方沒反對的就算達成共識。
3. 選項式提問元件（`AskUserQuestion`）一次最多 4 題——**那是工具的 UI 上限，不是設計原則**。受限時分批，並說明是工具限制；對方直接打字回答時就一次收完。
